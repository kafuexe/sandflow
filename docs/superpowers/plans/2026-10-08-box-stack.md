# Box Stack, run flags and grouped run history — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `stack` block that runs one child flow many times concurrently under an orchestrator (split → children → combine), plus saved run flags, alert popups and a grouped Agent run list.

**Architecture:** Stack children are real runs started by the engine through a recursive `startRun` call (new options `parent`, `stack`, `entry`, `depth`, `share`), registered by the API through an `onSpawn` hook. Flags live on `RunState`, raised through `ctx.flag`, copied up to the parent, and broadcast on `/api/data/events` as an SSE `flag` event. The orchestrator's split and combine are calls to the existing AI runner with a synthetic `ai` config; the engine parses the split's JSON.

**Tech Stack:** TypeScript, Node, React 19 + zustand + Tailwind/shadcn, vitest, @ai-hero/sandcastle.

**Spec:** `docs/superpowers/specs/2026-10-08-box-stack-design.md`

## Global Constraints

- Defaults: `maxConcurrent` 3, `maxChildren` 12, `maxRetries` 1, `successExits` `["done"]`, `workspace` `"isolated"`.
- Stack node exits are fixed: `done`, `failed`.
- Isolated child branch: `<parent-branch>-stack-<index>-<slug>` (a `/`-nested name collides with the parent ref in git). Base branch = parent branch.
- Flag tone is orange (`text-orange-300` / `bg-orange-400`, lucide `Flag`); amber stays "needs your answer", red stays "failed".
- Warning popups auto-dismiss after 10 s (paused on hover/focus); error popups stay.
- Copy is sentence case, plain verbs; no new UI libraries.

## Review Focus

- A child that asks a question must not block its siblings, and answering it via `POST /runs/:childId/answer` must work → engine test in Task 4.
- Cancelling the parent while children are queued must leave no child running and none started afterwards → Task 4.
- Shared workspace: concurrent children must not create two sandboxes → `getSandbox` memoises a pending promise (Task 5 test).
- Run list with many children must not push top-level runs out of the 50-run window → `listRuns` limits top-level runs only (Task 2 test).
- A failed top-level run that is later dismissed must stay dismissed after reload (the interrupted flag is computed on read) → Task 1 storage test.

### Task 4: Stack execution in the engine

**Files:** `backend/engine.ts` (new `runStack` helper in `backend/stack.ts`). Test: `test/stack.test.ts`.

**Interfaces — Consumes:** Tasks 1–3. **Produces:** stack nodes produce `{ outputs, exit: "done" | "failed" }`.

Algorithm (in `backend/stack.ts`, `runStack(ctx, node, cfg, inputs, spawn): Promise<NodeResult>`):
split via `runners.ai` with cfg `{...cfg, kind: "ai", instructions: splitInstructions + JSON protocol, outputs: {artifact: true}}` → parse, re-ask up to 2 times with the problem appended (invalid JSON / more than `maxChildren`) → normalise → worker pool of `maxConcurrent` over a queue of `{index, attempt}` → each attempt `spawn(...)` child run with `entry: { artifact: prefix + task.input, steer: inputs.steer }`, awaits `done`; success = `status === "done"` and `result.exit ∈ successExits`; else re-queue while `attempt <= maxRetries`, else dropped → combine via `runners.ai` with successful outputs (labelled `## <task>`; Isolated adds `Branch: <name>`) → flags → return. Abort: on `ctx.abort` cancel all live children and stop dequeuing.

- [ ] Tests: peak concurrency ≤ maxConcurrent; retry carries previous reason; drop → combine excludes + warning flag on parent; all fail → `failed` + error flag; invalid split re-asks; too many tasks re-asks; cancel parent cancels children; child question doesn't block siblings; child runs carry `parent`/`stack`; isolated child branch name.
- [ ] Implement; commit `Box Stack: split, concurrent children with retries, combine`.

### Task 5: API + sandbox wiring

**Files:** `backend/api.ts`, `backend/runners/ai.ts`, `backend/runners/auto.ts`. Test: `test/api.test.ts`, `test/ai.test.ts`.

- `launch` passes `onSpawn` registering the child handle in `runs` with the same save/listener logic (throttle per run id) and `onFlag` that broadcasts for root runs.

- [ ] Tests: API lists children with `parent`; flag SSE event emitted once for a child flag (root copy only); getSandbox concurrent calls create once; merge lock serialises.
